Reports invalid DataSyncLib annotation contracts and field configuration in Java code.

  • Unresolved method or field references, non-static referenced fields, missing required attributes, and method signatures that do not match the annotation contract.
  • Duplicate managed field keys, including fields flattened through @AdditionalHolder.
  • Invalid @SaveToDisk.defaultValue numeric literals and @Generic fields without resolvable generic type arguments.
  • Missing @Codec read methods when corresponding write methods are configured, and instance codec attributes ignored when saveCodec is set.
  • @Conversion function input types and @Strategy generic types that do not match the declared field type.

Method signature checks use the effective managed type when a field has @Conversion.

For example, the listener below cannot be resolved because the holder has no matching method:


class Holder {
    @SyncToClient(listener = "onEnergyChange")
    private long energy;
}

Add a matching method such as void onEnergyChange(long newValue, long oldValue), or update the annotation to reference an existing method. Place the caret on the method-name string and use Generate referenced method to create a method skeleton.

The checks mirror DataSyncLib's annotation member resolution and field configuration rules to help identify runtime reflection and configuration errors in the editor.
